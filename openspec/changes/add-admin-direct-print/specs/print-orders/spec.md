## ADDED Requirements

### Requirement: 後台直接列印原檔
後台 PDF 預覽 MUST 在「下載 PDF」旁提供「列印」操作。按下後系統 SHALL 以管理員既有授權，從與下載相同的管理員原檔路徑取得該訂單原始 PDF，不轉圖、不改寫，並對該 PDF 叫出瀏覽器列印對話框。色彩、雙面、縮放與印表機由管理員在對話框選擇，系統 MUST NOT 預設或覆寫。列印操作 MUST NOT 改變訂單付款或列印狀態，也不新增或修改 API。「下載 PDF」MUST 維持原行為。目標環境為 Windows 桌面 Edge（Chromium）；瀏覽器表示沒有內建 PDF 檢視器時 MUST 不顯示「列印」。

#### Scenario: 叫出列印對話框
- **WHEN** 管理員在 Chromium 桌面瀏覽器開啟某筆訂單預覽並按「列印」
- **THEN** 系統向 `/api/orders/{id}/file/{file_name}` 取得 PDF，交給列印的內容與原檔 bytes 一致，並對該 PDF 叫出列印對話框

#### Scenario: 列印不改變訂單狀態
- **WHEN** 管理員按「列印」並在對話框中完成或取消列印
- **THEN** 該訂單 `is_printed` 與 `is_paid` 維持原值，必須由管理員另行切換「已列印」

#### Scenario: 沒有內建 PDF 檢視器
- **WHEN** 管理員在回報沒有內建 PDF 檢視器的瀏覽器（例如 Android Chrome）開啟訂單預覽
- **THEN** 不顯示「列印」按鈕，「下載 PDF」照常可用

#### Scenario: 下載功能保留
- **WHEN** 管理員在同一預覽視窗按「下載 PDF」
- **THEN** 仍以原檔名下載與先前相同的原始 PDF

### Requirement: 列印準備的失敗與中止處理
列印準備期間「列印」按鈕 MUST 停用並顯示準備中狀態，避免重複請求。取得原檔失敗時系統 MUST 顯示錯誤並建議改用「下載 PDF」，不得叫出列印對話框，按鈕恢復可用。準備尚未完成就關閉預覽或改開其他訂單時，系統 MUST 放棄該次列印，不得對舊訂單叫出對話框。暫存的列印框架與 blob URL MUST 在下一次列印或關閉預覽時清除。

#### Scenario: 準備中不重複送出
- **WHEN** 管理員按「列印」後、原檔尚未取得前再次按「列印」
- **THEN** 按鈕為停用狀態，系統只送出一次原檔請求

#### Scenario: 原檔取得失敗
- **WHEN** 原檔請求回應 401、404 或網路錯誤
- **THEN** 顯示含錯誤原因並建議改用「下載 PDF」的提示，不叫出列印對話框，「列印」按鈕恢復可用

#### Scenario: 準備中關閉預覽
- **WHEN** 管理員按「列印」後、原檔尚未取得前關閉預覽視窗或開啟另一筆訂單
- **THEN** 不對原訂單叫出列印對話框，頁面上不殘留暫存列印框架，對應 blob URL 已撤銷
